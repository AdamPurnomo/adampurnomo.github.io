00 · Foundation

The big picture

Every layer solves a different problem. Confusing a TCP connection with an HTTP request—or an LB's flow mapping with a TCP endpoint—is the source of most networking misconceptions.

LayerResponsibilityImportant abstraction
L7 · ApplicationHTTP (Hypertext Transfer Protocol), SSE (Server-Sent Events), WebSocketRequests, responses, events, messages
L4 · TransportTCP (Transmission Control Protocol) / UDP (User Datagram Protocol)Ordered byte stream / independent datagrams
L3 · NetworkIP (Internet Protocol)Addressed packets & routing
L2 · LinkEthernet and related link protocolsLocal network frames
One sentence to memorize: TCP moves an ordered stream of bytes between endpoints. HTTP interprets those bytes as messages. SSE formats one streaming HTTP response; WebSocket introduces a bidirectional framing protocol. A load balancer either forwards the packets or terminates and proxies the connection.

01 · Transport lifecycle

What does an established TCP connection mean?

A connection is logical state in the endpoint operating systems, not a dedicated wire. Both kernels track the peer IP and port, sequence/acknowledgment progress, TCP state, buffers, receive windows, and timers.

One example four-tuple
Client
192.0.2.10:50000
↔
IP network
routers / LBs
↔
Server
198.51.100.20:8080

Three-way handshake

① SYN
Client → Server: SEQ 1000

Client announces its Initial Sequence Number (ISN). Client enters SYN-SENT.

② SYN-ACK
Server → Client: SEQ 5000, ACK 1001

Server selects its own ISN and acknowledges client's SYN. Server enters SYN-RECEIVED.

③ ACK
Client → Server: SEQ 1001, ACK 5001

Final acknowledgment. The client is now ESTABLISHED; the server becomes established when it receives this ACK.

Why +1? SYN consumes one sequence number, even when it has no application payload. A pure ACK consumes zero sequence numbers.

Graceful close

StepSegmentEffect
1Client FIN, SEQ 1006Client closes its sending direction; FIN consumes one sequence number
2Server ACK 1007Server acknowledges client's finish; its sending direction may still be open
3Server FIN, SEQ 5003Server finishes its sending direction
4Client ACK 5004Both directions closed; active closer commonly enters TIME-WAIT
Half-close: TCP is full duplex. Each direction can finish independently. When all buffered data is consumed after a peer's FIN, recv() returns zero bytes. A reset (RST) is an abort, not graceful FIN shutdown.

02 · Wire format

What's actually inside a TCP packet?

In this simple IPv4 example, an IP packet contains an IPv4 header, then a TCP header, followed by zero or more application bytes.

TCP header20 B minimum
Application payloadVariable length
TCP fieldWidthMeaning
Source/destination ports16 + 16 bitsApplication endpoints
Sequence number32 bitsFirst payload byte's stream position (or ISN for SYN)
Acknowledgment number32 bitsNext sequence number expected from the peer
Data offset4 bitsHeader size in 32-bit words
Control flagsBitsSYN, ACK, FIN, RST, PSH, etc.

Decode a real 40-byte illustrative SYN packet

Tap any byte to inspect its field. All values are internally consistent: a 20-byte IPv4 header + a 20-byte TCP header; no payload or TCP options.

Hexadecimal bytes · click to inspect
45 00 00 28 12 34 40 00 40 06 3c 4a c0 00 02 0a
c6 33 64 14 c3 50 1f 90 00 00 03 e8 00 00 00 00
50 02 ff ff dc c7 00 00

For example, at TCP offsets 4–7, 00 00 03 e8 equals sequence number 1000. At TCP offsets 12–13, 50 02 indicates a 20-byte TCP header with SYN set. IPv4's protocol value 06 means TCP.

Important distinction: the TCP header has no standalone payload-length field. Over IPv4, calculate payload length as IP total length − IP header length − TCP header length (assuming the complete reassembled IP payload).
03 · Packet sizing

How does TCP split application bytes?

A single application send() is not a single TCP packet. TCP divides its continuous byte stream into segments, with variable payload sizes constrained by the network path and endpoint capabilities.

1,500 B
Common Ethernet MTU
20 B
Minimum IPv4 header
20 B
Minimum TCP header

MTU = Maximum Transmission Unit. MSS = Maximum Segment Size, the TCP data payload size. Under our simplified 1,500-byte IPv4/Ethernet assumption, 1500 - 20 - 20 = 1460 bytes.

Interactive TCP segmentation


The packet size is variable. A 5-byte write may be sent in one small segment. A 4,000-byte write could become 1,460 + 1,460 + 1,080 bytes of TCP payload. Small writes may be coalesced; segmentation offload may move segmentation work to the Network Interface Card (NIC).

The TCP sequence number advances by the payload bytes sent, not by the number of packets. For payloads of 1,460, 1,460, and 1,080 starting at SEQ 1001, segment starts are 1001, 2461, and 3921.

04 · Reliability

Sequence numbers, out-of-order packets, and ACKs

TCP sequence numbers identify byte positions, not packet indices. The receiving kernel can buffer later bytes until missing earlier bytes arrive, producing an ordered stream to the application.

ACK = Acknowledgment. ACK 1006 means "all bytes before 1006 arrived; send me 1006 next." If C arrives ahead of B, the ordinary cumulative ACK remains 1006. Once B arrives, it jumps to 1016.

Packet loss

Missing bytes can be retransmitted with their original sequence numbers. TCP detects missing data through acknowledgment signals and/or timers.

Duplicate packets

TCP uses sequence ranges to avoid delivering retransmitted data twice. SACK (Selective Acknowledgment) can also report out-of-order ranges.

A 32-bit sequence number wraps modulo 2³². It never grows into a bigger field or gets more expensive to increment. TCP's ordered-delivery guarantee applies to bytes successfully delivered before a connection fails.
05 · Flow control

Can TCP backpressure a sender?

Yes. The receiver advertises a receive window (rwnd) in the TCP header. This tells the peer what additional byte range it may send without overflowing the receiver's available space.

Adjust an illustrative 64 KiB receive buffer
Used receive buffer16 / 64 KiB
48 KiBAvailable space
49,152Illustrative advertised window (bytes)
OPENReceiver status

Not a literal buffer dump: only a 16-bit Window Size value is placed in the TCP header (plus scaling negotiated in SYN options). The simulator shows an effective window; advertising 65,536 bytes requires scaling or a different window-management choice. The receiver's actual memory buffer is never sent over the network.

06 · Implementation

Who actually implements TCP?

Normally the Linux kernel, not your HTTP framework and not the Network Interface Card (NIC). A TCP server's application uses socket system calls; the kernel handles the TCP state machine and byte-stream reliability.

One Linux host, top → bottom
Application · Python / Java / Netty / Nginx
HTTP parsing, business logic, socket read/write
↓ socket() / bind() / listen() / accept() / recv() / send()
Linux kernel · socket / TCP / IP stack
Handshake, ACKs, retransmission, reordering, buffers, routing
↓ device driver, Direct Memory Access (DMA)
NIC · hardware
Ethernet frames, transmit/receive queues, checksum & segmentation offload

For a listener, the kernel can complete the three-way handshake and queue an established socket for accept(). The application does not manually parse incoming SYN packets.

Linux sourceWhat to study
tcp_input.c ↗Incoming segments, ACK processing, receive-side logic
tcp_output.c ↗Outgoing TCP segment construction
tcp_timer.c ↗TCP timers / retransmission support

An event-driven server using epoll can manage many TCP sockets without one OS thread per connection. Netty is a Java networking framework; its TCP server uses kernel TCP, and its HTTP codecs add HTTP parsing in user space.

07 · Application protocol

HTTP is messages carried by a TCP byte stream

HTTP/1.1 is a text-framed application protocol. TCP provides ordered bytes; HTTP supplies the rules for recognizing request lines, response headers, message bodies, and message boundaries.

Request

GET /a HTTP/1.1\r\n
Host: example.com\r\n
\r\n

Response

HTTP/1.1 200 OK\r\n
Content-Length: 2\r\n
\r\n
OK

\r\n denotes carriage-return and line-feed bytes. A blank header line (\r\n\r\n) ends the header block. Content-Length tells the parser how many response-body bytes to consume.

Keep-alive: multiple HTTP/1.1 requests, same TCP connection
SYN
TCP established once

Client ↔ server exchange initial sequence numbers.

GET #1
Request /a → response “OK”

Client and server advance their independent TCP sequence numbers.

GET #2
Request /b → response “HI”

No new handshake; the same sockets remain ESTABLISHED.

FIN
TCP closes later

After idle timeout, Connection: close, or another close decision.

TCP is stateful; HTTP is stateless in a different sense. TCP keeps transport state (sequence numbers, buffers, ACKs). HTTP doesn't automatically remember your identity, login, or shopping cart. Apps may implement sessions with cookies, tokens, or storage—and those sessions can survive TCP reconnects.

What HTTP/2 changes

HTTP/2 allows multiple independently identified HTTP streams to share one TCP connection through binary frames. A long-lived stream can coexist with ordinary requests. They still share TCP's ordered byte delivery, so TCP loss can stall them collectively.

HTTP/3 uses QUIC (a transport built over UDP) instead of TCP. HTTPS over TCP adds TLS (Transport Layer Security) between HTTP and TCP.

Why SSE ordering isn't durable event delivery

id: 41
data: job started

id: 42
data: step finished

id: 43
data: job completed

If the connection drops after event 42, a browser's EventSource can reconnect with Last-Event-ID: 42. The server must maintain event history and implement replay if the client is supposed to receive event 43. TCP only guarantees ordering of bytes successfully delivered inside a connection.

SSE is not “one event = one TCP packet.” An SSE event can span segments, or multiple events can share a segment. HTTP/SSE framing is what reconstructs application events.
09 · Application-layer load balancing

How L7 proxies map requests and streaming responses

An L7 reverse proxy is a TCP server to its downstream client and a TCP client to its upstream backend. It can inspect HTTP and select a backend based on host, path, headers, or other HTTP attributes.

For an SSE response, the proxy must maintain an association between the incoming request/response and its chosen upstream exchange until the streaming response ends:

downstream_http_exchange → upstream_http_exchange
client stream #1        → backend stream #7
client stream #3        → backend stream #9

With HTTP/1.1, each active SSE response ordinarily occupies its connection. With HTTP/2, multiple SSE responses can be separate logical streams on one TCP connection, so the mapping is stream-to-stream, not necessarily socket-to-socket.

Streaming gotcha: The proxy may buffer response data, delay events, or hit idle timeouts. It should stream incrementally and manage backpressure. It doesn't have to parse SSE event contents to relay the bytes.
10 · Transport-layer load balancing

L4 packet forwarding vs. an L4 TCP proxy

L4 means routing decisions are based on transport/network information—not HTTP content. But L4 does not tell you whether the balancer terminates TCP. These are two distinct implementation strategies.

Architecture A · packet forwarding

One end-to-end TCP connection

LB selects the backend, then forwards/rewrites packets (e.g. Destination NAT). The original SYN and sequence numbers continue to the backend.

Endpoint TCP states: client + backend. LB state: flow mapping / tracking, not a retransmitting TCP endpoint.

LB accepts the client's TCP stream and opens or uses a separate TCP stream toward the backend. Each has independent SEQ/ACK and buffers.

Why passing through the LB doesn't create another connection: The internet already sends TCP through many routers. Number of network hops ≠ number of TCP connections. An additional TCP connection exists only when the intermediate device participates as a TCP endpoint.

DSR (Direct Server Return) is another L4 variation: the LB handles inbound traffic and the backend sends replies directly to the client using the service IP identity. This reduces LB response bandwidth but requires suitable network configuration.

11 · AWS example

AWS NLB vs. ALB: what changes?

NLB = Network Load Balancer; ALB = Application Load Balancer. NLB makes flow-oriented decisions; ALB is an HTTP-aware application proxy.

AWS configurationConceptual pathImportant nuance
NLB TCP listenerL4 TCP pass-through / forwarding modelNo HTTP parsing; backend selected for life of TCP flow
NLB TLS listenerTLS/TCP termination at NLB; separate upstream TCP connectionTLS listener acts as a terminating proxy
ALB HTTP/HTTPS listenerL7 HTTP reverse proxyCan route by HTTP properties and manage independent frontend/backend connections
AWS documented facts: For TCP traffic, NLB selects one target for a connection's lifetime using a flow hash. NLB TCP idle timeout defaults to 350 seconds and can be configured to 60–6,000 seconds. TLS termination at NLB also terminates the TCP connection and establishes an upstream TCP connection.

Client IP preservation depends on target type and target group protocol. For example, AWS documents it enabled by default for instance-type TCP target groups and disabled by default for IP-type TCP target groups. That changes what source IP the target sees, not the conceptual difference between forwarding and proxy termination.

AWS internal packet-processing and flow-state implementation details are not fully public; these descriptions are networking models consistent with AWS's documented external behavior. See the primary AWS references at the end of this guide.

What happens if the backend dies?

With either model, an ongoing stream tied to that backend normally breaks. The LB can't make a different server magically inherit the original TCP sequence state or unfinished SSE response. The browser can reconnect; reliable missed-event recovery needs id, Last-Event-ID, and a replay-capable application.

What happens if the client is slow?

With L4 forwarding, TCP flow control works between the client and backend. With an L7 proxy, flow control applies separately to both TCP legs; the proxy must bridge downstream pressure into upstream read throttling.
